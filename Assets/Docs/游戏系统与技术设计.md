# 游戏系统与技术设计（原型分析 v0.1）

更新：2026-10-06。依据：[中控室原型](<古堡中控室_可点击原型.html>)、[含开场与地图的扩展原型](<古堡中控室_可点击原型 (3).html>)及策划演示。以下是程序设计依据，不是最终策划案；原型里能点击的按钮不自动成为开发需求。

## 1. 玩家在玩什么

玩家在**当下的古堡**交谈、取得地图和记录，主要在**中控室**调查前一晚由不同设备留下的录音。设备显示的时间未必准确；玩家听录音、看转写、对照声音与其他证据，提出“哪些片段记录了同一事件、事件真正何时何地发生”的假设，再提交验证。调查册保存原文、来源、草稿和已证实的结论。

原型展示的完整链路如下，其中“身份、人物路线、最终物证、结局选择”尚不能视为正式玩法范围：

```text
进入古堡/交谈 → 中控室浏览录音 → 标记声音锚点
→ 跨设备配对并校时 → 在历史地图上推断声源与门状态
→ 联合验证，生成事件卡 → 可选的身份/路线/最终关系推理 → 真相呈现
```

**示例题的解法**：REC-01 设备显示从 21:25 开始，文件内 05:00 的碰撞报时 21:30；REC-02 显示从 21:22 开始，同类碰撞在文件内 05:00 报时 21:27。如果证据支持两者是同一事件，REC-02 的时钟需校正 **+03:00**，事件时间才对齐到 21:30。原型还要求声源在餐厅、门关闭且有门状态证据，才能确认事件。**设备所在房间不等于声音发生的房间。**答错时保留草稿，可回看来源再修改，没有演示传统的“死亡/失败”。

扩展原型把示例声源写为“餐厅”，早期版本为“大厅”；部分其他房间名称也变化。以正式策划表为准，程序只用稳定 ID 关联，不用房间显示名作逻辑键。

### 已观察到的原型边界

- 原型“播放录音”是文字计时和逐段高亮，**两份 HTML 都没有实际音频文件或音频播放**。Unity 版要另做真实播放和转写同步。
- 网页将对白、答案、界面和状态写在一份脚本里，以浏览器 `localStorage` 存档；适合演示，不适合直接移植。
- 扩展版加入邀请函、对白中的可点击“地图”词、当前古堡导航图、时间开放房间和调查册。当前导航图与历史声音推理图是两种不同操作。
- 设置、尚未定位的设备、部分地图房间及后段演出有占位内容；不按按钮数量估算工期。网页内嵌的图片和字体也不是可直接交付 Unity 的独立美术资源。

## 2. 第一阶段目标与胜利判定

**建议先做一个可玩小题，不先复制整份网页。**使用两台设备、两段真实占位音频、各一条转写声音片段和一项时间校正；让玩家完成“听/读 → 标记 → 配对 → 校时 → 提交 → 事件入册”。房间或门证据若策划确认是核心，再纳入同一题。先保证玩家知道目标、能找到依据、答错能改、答对会推进。

暂定通关模型：一关配置若干**必解推理题 ID**，全部验证成功后触发真相/结局；错误提交不清除已收集资料。原型中的“身份、路线、最终证据”可作为额外题型接入，不应写死为每关都必须做。正式的胜利条件、反馈粒度及是否限制猜测，由策划确认。

## 3. 数据、状态与系统边界

**将三种信息分开**：①案件真相和正确答案（只供规则层读取）；②玩家已经发现的录音、道具、原文及来源；③玩家尚未确认的配对、校时、声源等草稿。界面可以显示后两种，不能因打开面板而泄露真相。

| 系统 | 职责与输出 |
| --- | --- |
| 流程/页面 | 当前场景、面板切换、解锁条件；中控室与调查册可来回打开，不重复触发奖励。 |
| 对话/交互 | 按数据展示说话者、正文、选项；通过条件和白名单动作取得地图、记录或解锁地点。 |
| 当前地图 | 显示人物现在的位置、可探索房间和开放条件；移动只影响当下状态。 |
| 录音/转写 | 播放、暂停、拖动进度；依据音频时间高亮转写片段，点击片段可跳转和摘录。 |
| 推理 | 管理锚点配对、设备校时、证据关联与草稿；提交时交给题型判定器。 |
| 历史地图 | 表达过去的房间、声源与门状态假设；不改变玩家当前所在位置。 |
| 调查册 | 根据发现与验证状态生成“人物、道具、事件、对话”视图；每条记录可追溯原始来源。 |
| 存档 | 保存进度、草稿、已确认题目、当前位置和对白节点；不把隐藏答案写入存档。 |

推荐调用方向：**UI 发起操作 → 当前会话处理 → 规则判定并更新玩家状态 → UI 与调查册刷新 → 存档**。不要让按钮各自改全局布尔值，也不要让调查册维护另一份独立事实。

### 首版数据契约

数据中的 ID 使用稳定 ASCII 标识，显示给玩家的名称与正文可以是中文；自研 C# 标识符遵循仓库中文命名规范。

| 数据 | 至少需要的字段 |
| --- | --- |
| 对话节点 | 节点 ID、说话者 ID、正文、下一节点/选项、进入条件、触发动作 ID。 |
| 房间/地图 | 房间 ID、楼层、图片区域或热点、可进入条件；导航连接与历史声学关系分开记录。 |
| 设备/录音 | 设备 ID、已知/未知位置、录音 ID、音频资源 ID、设备报时起点、录音时长。 |
| 转写片段/锚点 | 片段 ID、录音 ID、文件内开始/结束秒数、正文、类型（对白/声音等）、可引用来源。 |
| 物证/题目 | 物证 ID、发现来源；题目 ID、所需证据、可接受的答案与成功后解锁内容。 |
| 玩家状态 | 已发现 ID 集合、当前对话节点、各题草稿、已确认题目 ID、当前地点与时间。 |

时间不能只存字符串“21:30”：至少区分**当下探索时间、录音文件内时间、设备报告时间、事件真实时间**，并带日期/“前一晚”信息。统一用整数秒计算；`真实事件时间 = 设备报告时间 + 该设备校正量`。原型的 +180 秒和 ±2 秒容差只是示例数据，不应成为所有设备的固定常量。原始报时永远保留，以便调查册说明校正依据。

## 4. 文案、美术与可点击文字的生产路径

文案可以在飞书表格写作，再导出 **UTF-8 CSV**。首版至少分为“对白节点/选项、录音及转写、物证、题目”几张表。Unity **编辑器导入器**读取 CSV，检查重复或缺失 ID、断开的下一节点、无效动作、超出音频时长的时间戳，再生成可供运行时读取的内容资源。运行时不读取 `.xlsx`，也不把对白写入 C#。音频、立绘、背景等通过单独的资源目录/目录表按 ID 绑定到 `AudioClip`、`Sprite`，替换素材无需改对白逻辑。

可点击文字使用受控标记，例如文案写 `请收下这份[[地图|grant_map]]`。导入时验证 `grant_map` 是已登记的动作 ID；显示层转为 TextMeshPro `<link>`，点击时通过 `TMP_TextUtilities.FindIntersectingLink` 取得 ID，交给交互系统执行“获得地图/打开地图”。只允许约定的动作类型，不执行表格里的任意 C#、HTML 或脚本。节点进度与一次性奖励要可存档，重复点击不得重复发放。

首版优先做**表格导入、校验报告和 Unity Inspector 预览**，文案可通过改表重导入。等真实剧本出现大量分支、作者频繁需要看关系图，再补可视化节点编辑器；现在做完整通用剧情编辑器会占用核心玩法工期。

## 5. Unity 实现路径

- **表现**：现有 Unity 2022.3.62f3 / URP 2D；主场景用 Canvas、TextMeshPro、独立面板/Prefab 实现中控台、调查册、对话和地图。屏幕外观换图，不影响规则数据。
- **音频**：每次仅一个调查录音由 `AudioSource` 播放；以实际播放秒数驱动转写高亮。点击转写定位音频，暂停、拖动、切换录音后都按同一播放状态刷新。声纹/水波先做可替换的视觉组件，不把它当作判定依据；占位可用音量驱动，正式效果再定。
- **规则**：对白解锁使用少量明确的条件/效果类型；推理题使用独立判定器，如“锚点同事件+校时”和后续可选的“声源+门证据”。先检查证据是否允许提交，再比较答案；失败只说明哪类关系未成立，避免直接泄露正确值。
- **存档**：JSON 写到 `Application.persistentDataPath`，带内容版本和稳定 ID。保存发现、草稿及已验证事实；读档后恢复界面和录音位置，但不要自动开始播放。网页的 `localStorage` 不复用。
- **协作**：主程负责内容契约、状态/判定/存档及整合；副程可负责 UI、地图/音频面板和视觉接入。实际文件与场景归属须双方确认；共享接口先定输入、输出和事件。

## 6. 实施顺序与验收

1. **框架切片**：定义内容 ID 与玩家状态；做页面导航、数据加载、错误报告和存读档。用极少量占位数据，不先制作全部 UI。
2. **核心可玩切片**：两段可播放音频及转写、锚点标记、候选配对、设备校时、提交、调查册事件卡。改表格文字后重导入，游戏应变化而无需改代码。
3. **策划案到来后扩展**：按正式题目决定是否实现声源/门状态、身份、人物路线、现时地图探索和结局演出；逐项替换占位素材。

首个验收例：参考设备的 05:00 锚点为 21:30，另一设备的 05:00 锚点为 21:27；玩家设 +03:00 并附上规定证据后通过，其他校时保留草稿并提示复核。重开游戏仍能看到原文、来源、草稿与已确认事件。**目前还没有 Unity 玩法实现或运行验证。**

## 7. 需要策划尽快回答

1. 最终玩家必须提交什么：只校准各录音时间，还是必须证明同一事件、声源、人物路线与因果关系？
2. 时间精度和规则：固定偏移、逐渐漂移，还是录音有截断/播放速度误差？可选时间还是自由拖动，允许多少误差？
3. 哪些证据必须真的听音频才能获得？是否提供完整字幕、可跳转转写和重复播放？
4. 第一关的正确答案、每一步的可观察线索、错误反馈和解锁顺序是什么？
5. 地图是实际探索的主要玩法，还是中控室外的少量入口？原型里的身份/路线/结局哪些必做？
6. 文案表由谁维护，何时给首版字段及 1 个完整小案件？音频和美术是否能提供独立原始文件？
