# 游戏系统与技术设计（第一版）

以《程序说明文档》为功能契约。参考 HTML 提供古堡素材、深绿/金色/纸张风格和档案台交互；旧原型固定答案、声音传播、身份猜测和双结局已退休。程序英文命名，中文用于 UI 和注释。

## 数据与发布

六张 CSV 以表头映射至 ContentRow，数据库与 Inspector 配置分离。导入候选数据库全量校验成功后才发布到 ContentV2.asset。Plot 单表替换仍检查全部引用。诊断记录物理行号，包括引号内换行。版本从 ContentVersion.txt 读取；数据库不保存玩家状态。

DeviceConfig 保存设备真值及可靠参照依据；MapConfig 保存表现和节点，不保存答案。Room.scene 在表字典缺失，因此通过 Map.Rooms 绑定背景。显示名不是主键。Plot.link_entry 根据 Entry.name 构建 TMP 链接，不解析自定义剧情标记。

## 会话状态

v2 存档使用 Unity 可序列化列表，不使用 JsonUtility 不支持的 Dictionary。物品数量、持久证据、独立磁带实例、已标记锚点、分析草稿、已知设备信息分别保存。

世界时间只在事件结算、中控室离开、房间休息时变化；房间移动本身不计时。窗口包含 start、排除 end。事件开始后不会因房间关闭而取消；完成后再返回安全房间。跨越已满足前置的关闭点启用 Plan B，同 goal 只结算一次；未完成日常事件次日重新检查。

中控室会话跨文件列表、分析、调查册等页面持续存在。读档不重建访问，离开房间时计时并清除会话。个人文件以录制时间和导入时间分别保存，增量导入不改录制时间。

## 可恢复结算

1. 开始事件持久化 ID、开始时间、现场房间和对白游标。
2. 末句停留完成时录音入库，但不发放事件奖励、不加世界时间。
3. 点击继续时消耗、奖励、goal、时间一次写入；重复继续和回看不会重发。
4. 判定正确先保存 PendingPuzzle，随后显示 success 奖励事件。继续后写入 Solved、设备认知，清除 PendingPuzzle。
5. 结局保存 playing/complete，跳过等同结束演出；回看只播放，不发奖。

普通保存先写 .tmp 并刷新文件缓冲，再替换主文件、保留 .bak；损坏时读备份。不兼容 v2 文件保护而不覆盖，v1 不碰。Unity JSON 的空嵌套对象读回可能成为空实例，构造会话时按空事件 ID 归一化。

## 推理

锚点集合不比较顺序，必须包含完整同次声响集合，且都已经标记。定位读取 Device.room，成功领奖前不公开。校时要求已经匹配的目标/参照声响，参照有 proof 或已校正；读取 Device.offset 和参照校正时间。校正时间=报告时间−已验证偏差，移动量=−偏差，步长和容差集中配置。

路径按 slots 顺序逐个保存候选节点，允许同一点再次出现。时间线候选仅显示已收录事件，槽位支持卡片交换，正确后锁定并显示 feedback。最终推论检查关联时间线已 Solved。错误保持草稿、时间和物品不变。

## 表现和扩展

CastleGame 只负责装配和生命周期；页面通过服务动作调用规则。uGUI 页面独立构建，TMP 使用中文动态字体；播放、拖动校时滑块、结局波形不销毁整页。弹窗遮罩接管输入、Esc 优先关闭弹窗。长对白和调查册/文件使用 ScrollRect。

当前 Prefab 是可替换页面壳，内部布局由工厂生成，完整设计师可视化布局迁移仍是表现层后续工作。环境/道具音按 Plot 行 ID 绑定；没有正式素材时使用占位提示。波形与字幕共享游标，未引入音频传播延迟模型。
