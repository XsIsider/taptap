# 协作与同步

## 日常操作

先确认当前分支与未提交修改，再 Fetch/Pull。每项独立任务从同步后的 master 创建功能分支；日常在自己的分支多次普通 Commit，测试后 Push，再用 PR 合并 master。不要在未确认当前分支时直接同步或提交。

VS2022 可完成创建/切换分支、查看差异、提交、拉取和推送。PR 是申请把功能分支合入目标分支，通常在 GitHub 网页检查差异和讨论后合并。一次 Push 可以包含多个 Commit，提交历史仍然保留。

合并后各自切换回 master 并 Pull，下一项工作再创建新分支。旧功能分支确认无未合入工作后才删除；储藏是本地临时保存，不会随 Push 共享。

有未提交工作先保存处理；冲突解决后再推送。已推送的提交不要修订或强推。

## 文档维护

- AGENTS.md：代码与开发规范。
- Assets/Docs/项目交接.md：当前玩法、实现状态、实际分工和待解决问题。
- 修改功能、接口、依赖或接入方式时，更新对应内容，与代码一起提交；小修复无需机械更新文档。
- 保持精简，只记当前事实和必要事项；历史通过 Git 查询，不重复抄写聊天记录。
- 飞书用于策划讨论和内容协作；确认后的技术结论进入仓库文档。
- 文档随 Push/Pull 同步，不是实时共享编辑，也不会自动同步到飞书。

## 交接最少说明

完成了什么、入口或挂接方法、接口变化、验证结果、待接入事项及负责人。
